## N10 — WGS 比对 QC（每样本）

**实现**
- 新规则（`rules/qc.oxoflow`，全部 `when = "wildcard.assay == 'wgs'"`，输入
  `bqsr/{sample}/{sample}.bqsr.bam(+.bai)`）：
  - `wgs_flagstat` → `samtools flagstat` → `qc/alignqc/{sample}.flagstat`
  - `wgs_bamstats` → `samtools stats` → `qc/alignqc/{sample}.stats`
  - `wgs_mosdepth` → `mosdepth --by 1000000 --thresholds 10,20` →
    summary/thresholds/regions 三个输出。**1Mb 窗口模式不落盘全基因组
    per-base 文件**（替代方案：`--by` 窗口 + `--thresholds` 直接给出每窗口
    ≥10x/20x 碱基数，覆盖度比例是全基因组碱基级口径，窗口平铺参考序列）
  - `wgs_alignqc_summary` → `scripts/collect_alignqc.py`（stdlib-only，按文件
    后缀路由，与 cohort_tables 同模式）→
    `qc/alignqc/wgs_alignqc_summary.tsv`（cohort 收集规则；空 DNA 组时输出
    header-only，报告链仍可解析）
- `multiqc`：扫描白名单加 `qc/alignqc`，expand_inputs 加 3 个 anchor
  （flagstat/stats/mosdepth.summary），三个 MultiQC 模块
  （samtools flagstat / samtools stats / mosdepth）全部按内容匹配。
- 并入 report 链：`cohort_tables.py` 增 `wgs_` 路由（患者级前缀列
  `wgs_mapped_pct` 等）+ `clinical_report.py` 新 `--alignqc` 段落
  "WGS alignment QC (per sample)"。

**工具版本**：samtools ≥1.21（与 envs/align、envs/rna 已验证版本对齐）；
mosdepth ≥0.3.10（bioconda 最新，2026-11）。两者已加入 `envs/qc/pixi.toml`。
⚠️ **lock 未在本机重生成**（本机无 pixi；按 docs/env_policy.md 须在目标平台
服务器执行 `pixi lock --manifest-path envs/qc/pixi.toml` 并随本分支提交）。
toml+lock 指纹变更会使 qc 组规则在下次 run 时重装环境（符合预期）。

**输出 schema**（`wgs_alignqc_summary.tsv`，一行/样本）：
`sample, total_reads, mapped_pct, duplicate_pct, insert_size_median,
insert_size_average, insert_size_stdev, gc_pct, mean_depth,
coverage_10x_pct, coverage_20x_pct, sex_x_ratio, sex_y_ratio, predicted_sex,
contamination_freemix`

**诚实披露点**：无降级；GC 为 reads 加权均值（samtools stats GC 段），
≥10x/20x 比例分母 = BAM header 参考序列全长（不含未挂载 contig）。

**测试**：`tests/test_alignqc.py`（13 个：flagstat 新旧格式、stats SN/GC、
mosdepth summary/thresholds 明文+gzip、性别判定各分支、乱序路由、空输入
header-only、未知后缀 fail-loud）。

## N11 — 性别核对 + 交叉污染

**实现**
- 性别：复用 N10 的 mosdepth summary.txt（每染色体均值行），无需新工具。
  `collect_alignqc.py` 内 `call_sex()`：autosome 均值（chr1..22 长度加权）→
  `x_ratio = chrX/A`、`y_ratio = chrY/A` → 判定（常量披露于脚本头部并在
  report 注释渲染）：
  - **M**：X/A < 0.75 且 Y/A ≥ 0.05
  - **F**：X/A ≥ 0.85 且 Y/A ≤ 0.02
  - **ambiguous**：两带之间；缺 chrY contig → `F(no_chrY_contig)` /
    `ambiguous(no_chrY)`；缺 chrX → `ambiguous(no_chrX)`
- 污染：**降级为 not_assessed**（见下）。`contamination_freemix` 列 =
  `not_assessed(no_genotype_panel_p2)`。

**诚实披露点（授权降级）**
1. 本 cohort 无性别元数据 → 判定是覆盖度筛查假设，非样本表修正；两阈值带
   之间（X/A 0.75–0.85）一律 ambiguous 不硬判。
2. **污染检测未做**：VerifyBamID2（bioconda `verifybamid2`）需要 1000G SVDP
   基因型参考面板（GB 级下载）+ 有意义的 cohort 密度才有可信 freemix；本
   cohort 为 tumor-only 类器官、10 患者。按任务授权降级为文档披露（本文件 +
   README + report 注释），列名显式 `not_assessed(no_genotype_panel_p2)`。
   **P2**：面板就位后加 `wgs_verifybamid2` 规则（envs/qc 补 verifybamid2），
   输出进同一汇总表替换标记列。

**测试**：性别判定 M/F/ambiguous/缺 contig 四分支在 `test_alignqc.SexCall`。

## N12 — RNA 融合筛查（增强，非替换）

**实现**
- `star_align`（`rules/rna.oxoflow`）补 chimera 旗标：
  `--chimSegmentMin 12 --chimOutType WithinBAM SoftClip Junctions
  --chimJunctionOverhangMin 12`。**核实结论**：STAR 仅在 `--chimOutType`
  含 `Junctions` 时才写 `Chimeric.out.junction`（默认 `WithinBAM HardClip`
  一个 junction 文件都不产，源码
  `ParametersChimeraic_initialize.cpp: out.junctions=false` 起始）——所以
  三件套缺一不可。`WithinBAM SoftClip` 使嵌合比对进主 BAM（IGV 可见）；
  featureCounts 已有 `-C`（排除嵌合片段对），count matrix 不受影响。
  **指纹变更，STAR 全量重跑**：下次 run 每个 bulkRNA 样本重新比对（约 10×
  16 线程小时级），须与计划的重跑窗口同步（README"Operating on a run
  workdir"已有此约定，规则注释也标注了）。
- 新脚本 `scripts/fusion_screen.py`（stdlib-only）：解析
  `Chimeric.out.junction`（STAR ≥2.5.1b 为**每 read 一行**格式，14/15 列含
  RG；`--chimMultimapNmax=0` 无表头），按位置规范化的 6 元组聚合（镜像
  junction 折叠）、unique read 数 = split_reads、锚定长度从 p-extended
  CIGAR 重算（M/I/=/X 和，披露于输出）、GENCODE GTF gene span 注释（含
  ±10kb promoter 近邻）、panel 匹配复用 clinical_sv 语义（无序 pair +
  `*` 通配单基因规则）。
- 新规则：`rna_fusion_screen`（每 bulkRNA 样本 →
  `rna/fusion/{sample}.fusion_candidates.tsv`）+ `rna_fusion_cohort`
  （`scripts/collect_fusion.py` → `report/fusion_screen_cohort.tsv`，panel
  hits 优先、split_reads 降序）。
- report：`clinical_report.py` 新 `--fusion-screen` 段，注释明示与 Manta BND
  面板**互补披露**（RNA junction vs gDNA breakpoint 两类证据），不替换。

**工具版本**：无新工具（STAR ≥2.7.11b 已在 envs/rna，chimera 为内建能力）。

**输出 schema**：`sample, fusion_pair, gene_a, gene_b, breakpoint_a,
strand_a, breakpoint_b, strand_b, motif, anchor_a, anchor_b, split_reads,
panel_hit, panel_label, evidence_class, disclosure`

**诚实披露点**
- 每行 `disclosure` 列写明：筛查级、仅 split-read 证据、无 spanning-fragment
  支持/转录本重构/RT-artifact 过滤、方向为 STAR read 序非 5'-3'、**需 RNA
  正交确认**。evidence_class 分层：`panel_hit` / `panel_hit_single_read`
  （保留并披露，不静默丢弃）/ `supported_Nreads`（≥3）/ `low_support_Nreads`。
  `--min-split-reads` 只管非 panel 候选（更严阈值不得悄悄丢弃可用药命中）。
- 全 STAR-Fusion 级重构需 CTAT genome lib（数十 GB 新索引）→ P2。

**测试**：`tests/test_fusion_screen.py`（12 个：CIGAR 锚定数学、镜像折叠、
唯一 read 聚合、panel 三种匹配形态、锚定下限、STAR-Fusion 表头跳过、空
junction header-only、cohort 排序、空输入列表）。

## N13 — scRNA ambient/doublet

**实现（采集式 + 诚实降级）**
- 核查结论：dnbc4tools 3.0 的 `metrics_summary.xls` 无 doublet/ambient 字段
  （`scripts/scrna_metrics.py` 的 KEY_ALIASES 表是该文件字段的实地审计产物，
  无相关键；审计 N13 同结论）。重算方案（DecontX/calcN 从 count 矩阵）判定
  过重，按任务授权走披露路线。
- `scrna_metrics.py`：输出表增 `doublet_pct` / `ambient_pct` 两列，无值时 =
  `not_assessed(tool_lacks)`（显式标记，不是空白不是 0）；同时加 KEY_ALIASES
  （`doublet_rate`/`ambient_fraction` 等）——未来 dnbc4tools 若开始上报，
  真值自动顶替标记，不用改代码。
- 下游自动流动：`cohort_tables` → `sc_doublet_pct`/`sc_ambient_pct` 列；
  clinical report 的 scRNA 段照常渲染（tsv_markdown 全列）。

**诚实披露点（授权降级）**：ambient/doublet 未测量，仅标记披露；README 新增
"scRNA ambient/doublet: not assessed" 段，注明 P2 可用受保护的
`raw_matrix/`（unfiltered MEX trio，当初就是为此保留的）引入 scDblFinder /
DecontX（scanpy 生态），无需重跑 dnbc4tools。

**测试**：`tests/test_scrna_metrics.py`（3 个：dnbc4tools 3.0 风格输入产出
标记列、未来版本真值顶替、模块常量/别名接线）。
